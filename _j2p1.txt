Concept

· Le Web est un ensemble de technologies interconnectées qui, combinées, forment l'internet

    tel qu'on le connaît. 1

· Les technologies fondamentales sont : HTML, CSS, JavaScript, HTTP, les URLs et le DNS.

         2

· HTML (HyperText Markup Language) est un langage de balisage sémantique : il décrit le

    sens du contenu, pas sa présentation visuelle. 3

· CSS est la technologie complémentaire qui prend en charge la présentation (mise en forme,

    couleurs, disposition). 4

· Le principe fondamental est la séparation du fond et de la forme : le contenu (HTML) est

    indépendant de la présentation (CSS). 5

Ce que j'ai compris

Histoire et origine du Web

· Le Web a été inventé par Tim Berners-Lee en 1989 au CERN. 2
· Il est issu d'un héritage des années 1960-1970, avec les langages GML puis SGML

    (normalisé par l'ISO en 1986), dont HTML est un dérivé créé en 1991. 6 7

· Le premier site web est encore consultable aujourd'hui via une émulation de la technologie

    de l'époque. 2

· HTML a connu plusieurs versions (3.2, 4, XHTML) avant de se stabiliser à HTML5, qui est

    désormais un standard vivant évoluant en continu sans numérotation de version. 7

Principe du balisage HTML
· HTML fonctionne par balises (tags) : on ouvre un contexte avec <balise> et on le ferme

    avec </balise> . 8

· Les balises s'imbriquent comme des poupées russes -- il ne peut pas y avoir de

    chevauchement : si <article> est ouvert avant <h1> , il doit être fermé après <h1> . 3

         9

· Le balisage est sémantique : on indique ce qu'est le contenu (titre, paragraphe, article), pas

    comment il doit apparaître. 3

· Analogie avec un traitement de texte : utiliser le style "Titre 1" plutôt que simplement mettre

    le texte en gras permet ensuite de générer automatiquement une table des matières --
    même logique en HTML. 10

Structure d'une page HTML

· <!DOCTYPE html> : première balise obligatoire, indique au navigateur la version HTML

    utilisée (aujourd'hui simplement html ). 11

· <html lang="fr"> : balise racine avec indication de la langue principale du document, utile

    pour la traduction automatique. 12

· <head> : contient les informations non visibles destinées au navigateur :
    Encodage des caractères ( charset="UTF-8" ) 13
    Titre de la page (affiché dans l'onglet et les moteurs de recherche) 13
    Liens vers les feuilles de style CSS et scripts JavaScript 14
    Métadonnées ( description , keywords ) pour le référencement 14

· <body> : contient tout le contenu visible par l'utilisateur. 14

    française) 25

· title : info-bulle affichée au survol de la souris 25

Balises auto-fermantes

· Certaines balises n'ont pas de contenu intérieur : ``, <hr> , <img> , <input> , <meta> ,

      <link> . 27

· Syntaxe recommandée : `` (slash avant le > ) pour indiquer qu'elles sont ouvertes et

    immédiatement fermées. 28

Commentaires et caractères spéciaux

· Commentaires HTML : <!-- texte --> , peuvent être multi-lignes, utiles pour désactiver

    temporairement du code. 28 29

· Caractères réservés à échapper obligatoirement : <  &lt; , >  &gt; , & 

      &amp; . 30

· &nbsp; (espace insécable) reste pratique pour la typographie correcte. 30
· En UTF-8, les accents et caractères non-ASCII n'ont plus besoin d'être encodés. 31

Blocs vs Inline

· Balises bloc ( <p> , <div> , <article> , etc.) : occupent toute la largeur disponible, les

    éléments suivants se placent en dessous. 32

· Balises inline ( <a> , <img> , <strong> , <span> , etc.) : s'intègrent dans le flux du texte

    sans provoquer de saut de ligne. 33

· Règle importante : on ne peut pas placer un bloc à l'intérieur d'un inline (ex. pas de <p>

    dans un <a> ). 34
Les URLs (Uniform Resource Locator)

· Structure complète d'une URL : protocole://domaine:port/chemin?paramètres#fragment 35
· Protocole : http , https , file , etc. -- définit la méthode de communication. 35
· Nom de domaine : lu de droite à gauche (TLD  domaine  sous-domaine), plus lisible

    qu'une adresse IP. 36

· Port : par défaut 80 pour HTTP et 443 pour HTTPS -- inutile de le préciser si on utilise le

    port par défaut. 36

· Chemin : peut correspondre à de vrais fichiers ou à une arborescence virtuelle (contenu

    dynamique). 37

· Paramètres ( ?clé=valeur&clé2=valeur2 ) : séparés du chemin par ? . 37
· Fragment ( #section ) : pointe vers une section précise dans la page ou utilisé par certains

    frameworks pour le routage interne. 38

· URLs absolues vs relatives :
    Absolue depuis la racine ( /chemin/page.html ) : conserve protocole, domaine et port,

          mais change si le site est déplacé dans un sous-répertoire. 39

    Relative ( ./page.html , ../image/photo.png ) : basée sur la position actuelle,

          recommandée car portable. 40

    URL complète : déconseillée si le domaine ou protocole peut changer (migration HTTP

           HTTPS, changement de domaine). 40

Séparation HTML / CSS

· HTML cinq a supprimé de nombreuses balises de présentation héritées des versions

    précédentes (ex. balises de mise en forme directe). 41

· La balise <b> (gras) existe encore mais il vaut mieux utiliser <strong> qui a une

    signification sémantique. 42

· Le CSS prend entièrement en charge la présentation : couleurs, tailles, polices, disposition.

Ce que je n'ai pas bien compris

Pourquoi <!DOCTYPE html> sans numéro de version ?

· À l'époque où coexistaient HTML 3.2, HTML 4, XHTML 1.1, etc., il fallait préciser exactement

    la version pour que le navigateur sache comment lire la page. 11

· Depuis HTML5 (standard vivant), il n'y a plus qu'une seule version active, donc on écrit

    simplement <!DOCTYPE html> sans préciser "5". 12

· Conseil : on le met quand même systématiquement pour éviter que d'anciens navigateurs

    interprètent mal la page.

Différence entre <strong> et <b> , <em> et <i> 

· <b> et <i> sont des balises de présentation (gras, italique) -- elles disent comment

    afficher. 42

· <strong> et <em> sont des balises sémantiques -- elles disent pourquoi c'est important

    ou mis en emphase. 18
· En pratique, les navigateurs affichent <strong> en gras et <em> en italique par défaut,

    mais le CSS peut changer cela librement -- c'est tout l'intérêt de la séparation fond/forme.

Pourquoi préférer les URLs relatives ?

· Si votre site est hébergé dans un sous-répertoire (ex. sur une plateforme académique),

    toutes les URLs absolues "cassent" car elles partent de la racine / qui ne correspond plus
    à la racine de votre site. 40 47

· Pareil si vous changez de domaine ou passez de HTTP à HTTPS : les URLs complètes

    deviennent invalides. 40

· Les URLs relatives, elles, fonctionnent quelle que soit la position du site dans l'arborescence

    du serveur.

Différence entre <p> et ``

· <p> crée un nouveau paragraphe : c'est une nouvelle unité sémantique de texte, avec

    espacement par défaut avant et après. 17

· `` est un simple saut de ligne visuel à l'intérieur d'un même paragraphe -- sans nouvelle

    sémantique. 48

· Mauvaise pratique : enchaîner plusieurs `` pour simuler des espacements entre paragraphes

    -- utiliser <p> à la place.

Le fragment ( # ) dans les URLs

· Sert à pointer vers un élément ayant un id spécifique dans la page (ex.

      page.html#section-contact scrolle jusqu'à <section id="section-contact"> ). 38

· Certains frameworks JavaScript anciens utilisaient le fragment pour gérer la navigation

    interne (routing côté client) -- cette pratique est moins courante aujourd'hui. 38
